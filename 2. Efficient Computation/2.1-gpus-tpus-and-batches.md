# Chapter 2 – Efficient Computation

Deep learning is modular and compositional where architectures can be composed and extended almost arbitrarily. It then follows that, from an implementation standpoint, it is much less about engineering features or curating information “outside” the model than about executing heavy computations on the data and letting the architecture learn representations. GPUs have been critical to the success of the field since they enable exactly this, which the author talks about in the upcoming section.

It becomes quite apparent as one goes through the book that deep learning is constrained not by representational capacity, but by what algorithms can actually run under computational constraints. Derivations such as the Universal Approximation Theorem show that _representational capacity is rarely the bottleneck in practice_. The balance that is constantly being maintained in the field then is: given the theoretical soundness of a method, how best this can be implemented under technical constraints.

# 2.1 GPUs, TPUs, and batches

GPUs possess highly parallel structures that happen to be well suited for deep learning. The key here is “_happen to be_.” GPUs weren’t originally designed for deep learning but for graphical processing. As they were increasingly used for deep learning, they were modified specifically for the field. Examples include the development of tensor cores and Google’s Tensor Processing Units (TPUs).

In general, the bottleneck is not computational capacity but read-write operations across different types of memory. There are different _levels_ of memory involved. The biggest bottleneck is, intuitively, the link between CPU and GPU memory. But the GPU itself has multiple levels of cache memory. The goal is to avoid copying as much as possible, both CPU to GPU and cache to cache within GPU.

To process computations, the GPU needs both the weight matrix and the sample near the actual computing unit. Processing samples individually is inefficient since the parameters need to be copied separately for each sample. Processing batches of samples at once significantly reduces data copying and allows copying the parameters once per batch. Moreover, processing a batch of samples is in practice not much more expensive than processing a single sample due to the highly parallelized architecture of GPUs.

A standard GPU, according to the book, has a _theoretical_ performance peak of 1013 - 1014 FLOPs per second. FLOPs is _floating-point operations per second_. It is the number of operations that can be performed on floats in a single second. A GPU, then, can process trillions or more of such operations each second. So the strength of a GPU is performing _trillions of simple numerical operations per second_. This works _perfectly_ for deep learning.

These floating points are represented typically in 32 bits (FP32). However, empirical results have shown that FP16 or even smaller encoding for certain operations does not degrade performance. Small disruptions to numerical precision average are often absorbed across the many computations performed by a neural network.

Again, everything here goes back to how engineering the flow has become such an important part of the field. The bottleneck is not usually the representational capacity of a deep learning model.
