# 2.2 Tensors

Tensors are the backbone of data processing in deep learning. They _standardize_ the process of data flow and computation. Formally, a tensor is a collection of one or more discrete series of scalars, each representing a specific axis. A tensor generalizes the notion of a vector or a matrix. A vector is a tensor. A matrix is also a tensor.

Tensor is the “general” representation infrastructure in deep learning. Tensors are used to represent the input signal, the trainable weights, the trainable biases, as well as the intermediate activations.
The book provides as example time series and images. A time series can be represented as a D x T tensor, where T denotes time steps and D denotes the _number of channels_. Similarly, an RGB image can have the shape D x H x W where D = 3 (one each for R, G, B). What is channel as a concept? It looks abstract, almost unnecessary at first, but the importance becomes clear as one progresses through the book.

A channel is one “way” of looking at the entire signal, distinct from other “ways.” Under a special structure of 28 x 32, a channel contains an activation for each of the 896 spatial locations. Assuming a total of 30 channels, each spatial location is represented, in its entirety, as a vector of 30 activations. Each of the 30 activations is a result of the respective channel interpreting the spatial locations through a different _lens_. In the case of RGB, the channels quite literally measure the intensity of red, green, and blue lights. A channel may also look for the presence of ears, across all spatial locations, in a prediction exercise of a cat face. This becomes _crucial_ to understand since these lenses can be used to modulate signal flow. They may be operated on for zooming in, zooming out, cropping, or even for pre-specified detection patterns.

A signal with 3 channels across a spatial structure of 28 x 32 can be represented as 3 x 28 x 32, which is a tensor. 50 such signals can be represented as 50 x 3 x 28 x 32. This is also a tensor. Tensors are thus generalizable representations.

Deep learning libraries are based on tensor modulation. But this is a _critical_ point: implementing operations as tensor manipulation creates separation between the _representation_ of the data operated on and how the data is _actually stored_. Tensors change the representation seamlessly _while_ leaving the storage layout unchanged. For example, the same block of memory [1,2,3,4,5,6] can be viewed as a 2 x 3 matrix, a 3 x 2 matrix, or a transposed array without necessarily moving numbers in memory. This makes for extremely efficient computations.

Tensors also help heavily parallelize computations and avoid sequential loops. Since most deep learning operations can be broken down into elementary operations, tensors are able to set these up to be processed parallelly across cores. An example subset is the computation of a fully connected layer being set up as matrix algebra as opposed to a for loop in Python.

Finally, everybody in a DL pipeline knows that the data will flow and be manipulated in tensors. This allows everyone, from researchers to engineers, to optimize their respective parts of the pipeline for tensor computations. Deep learning is, at its core, about processing a _massive_ number of _elementary_ operations. It is simplistic (not necessarily easy) elegance at scale. Both tensors (as the abstract representation) and GPUs (as the hardware) then focus on parallelizing this for maximum efficiency.
