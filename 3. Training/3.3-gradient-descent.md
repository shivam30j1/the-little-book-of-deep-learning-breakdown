# 3.3 Gradient Descent
The parameters of a model must be optimized to minimize the loss function. They must then be optimized somehow _in relation to_ the loss. Certain algorithms, like the linear regression, have closed form solutions which represent a finite number of mathematical operations to calculate the precise set of parameter values. In most cases, mappings are complex enough to where there are no closed form solutions to the optimization problem. There’s no “equation to plug into” to get the most optimal parameter values.

There must then be a way to (a) start somewhere w.r.t. parameter values and (b) move them closer to the “optimal” values. One way to do this is gradient descent (GD). GD starts with initializing weights either randomly or according to specific techniques. It then provides a direction from the initialized values using the gradient (a vector of the respective partial derivatives of the loss with respect to each of the parameters), which is mathematically the direction of the steepest ascent. The negative of the gradient is then the direction of the steepest descent, or the direction that decreases the loss with respect to the parameters maximally, locally. It points to where the descent is the steepest downward. A higher magnitude of the gradient vector corresponds to a steeper descent.

However, the gradient does not answer how far the bottom is. The actual steps towards the local minimum are thus modulated by a learning rate, which is a hyperparameter and usually a very small number. Formally, for a weight wn and a learning rate α,

\[
w_{n+1} = w_n - \alpha \frac{\partial L}{\partial w_n}
\]

Picturing the plot of the loss against all weights as a complex cliff, gradient descent starts with some w (the vector of all weights). It then identifies the steepest direction of decrease from w. The actual steps taken towards that local minimum are iterative and scaled by the learning rate. The choice of learning rate is very important, since the gradient only provides the direction but not the distance to the bottom. A large learning rate can cause the algorithm to overshoot and miss the minimum entirely; a small learning rate will update the weights very slowly.

Stochastic Gradient Descent
Most losses are some average of individual losses per sample. The gradient is then computed for each sample, aggregated across samples, and then averaged. This average can then be used to update the parameters, but this process is very computationally heavy (datasets can be very large).

Now, assume that the data follows reasonable exchangeability rules where shuffling the data does not change its statistical properties. Any batch of properly shuffled samples drawn from the data is an unbiased estimator of the overall gradient, with some error e. Calculating the gradient at the batch level and updating weights therefore corresponds to eventually and very gradually minimizing the loss with a greater number of noisier steps. This is the process of Stochastic Gradient Descent, which mitigates the computational bottleneck of making a single update to the gradient using the entire dataset. This can either be performed at the batch level or at the individual sample level.

A specific variation of gradient descent called Adam optimizes the learning process by bringing into the picture the running means and variances of the individual parameters within the gradient. The details are left beyond the scope of these notes.
